1. EXECUTIVE SUMMARY & DEFECT IDENTIFICATION
--------------------------------------------------------------------------------
During the Python certification expansion (commits 9797c338 and 5d887012), 
Days 31 to 60 of Course 12 (Production AI Safety & Alignment, `safe-py`) were
generated by a batch expansion script that emitted the JSON key `"partNumber"`
instead of `"part"`.

The TypeScript interface `LongLessonPart` (defined in src/lib/data/longLessonTypes.ts)
explicitly declares:
    export interface LongLessonPart {
      part?: string | number;
      ...
    }
Because TypeScript strict object literal checking forbids undeclared properties,
the compiler raised 150 instances of:
    error TS2353: Object literal may only specify known properties, 
    and '"partNumber"' does not exist in type 'LongLessonPart'.

--------------------------------------------------------------------------------
2. ROOT CAUSE FORENSICS
--------------------------------------------------------------------------------
- Toolchain Blind Spot: The project runs targeted tests using `tsx` (esbuild),
  which strips types without performing static type-checking. Therefore, the
  runtime tests passed completely even while `tsc` was failing with 150 errors.
- Key Inconsistency: Days 1 to 30 omit the `part` property entirely (relying
  on `part?` being optional). Days 31 to 60 attempted to number parts 1 to 5
  using `"partNumber": N`.
- Consumer Dependency: Codebase inspection across all files in `src/` confirmed
  that ZERO application consumers read `.partNumber`. All lesson UI components
  iterate through `lesson.parts` as an array and compute part display numbers
  from array indices or read `part.part`.
