Day 38: The Universal Object Contract: equals(), hashCode(), and Reference Identity (==)

Stage 2: Defensive Fluency Month 2 • Block 8 • 4 Quests
🎯 Spoken Goal & Invariant:
Goal: Master java.lang.Object core methods. Understand why overriding equals() requires overriding hashCode(), and the catastrophic consequences of breaking this contract.
Invariant: If two objects are equal according to equals(Object), calling hashCode() on each must produce the exact same integer value. == compares memory addresses; equals() compares field values.
⚠️ Failure Mode & tryIt Bug:
Failure: Failing to override hashCode() when overriding equals() causes HashSet and HashMap to duplicate keys or return null on lookups of mathematically identical objects.
tryIt Friction: Override both equals() and hashCode() on an AccountKey class so that set.contains(new AccountKey("ACC-101")) correctly evaluates to true.
💡 3-Tier Socratic Hint Ladder: [1. Nudge: "Why does set.contains(new AccountKey("ACC-101")) return false even though an AccountKey with "ACC-101" was already added?"] → [2. Memory: "Because without overriding hashCode(), Java uses System.identityHashCode (memory address). The two instances land in completely different hash buckets!"] → [3. Fix: "Implement consistent equals() and Objects.hash(id) to ensure identical keys map to the exact same bucket."]
🧩 Situational Diagnostic Puzzle: "An engineer creates a class CurrencyPair { String base; String quote; } and overrides equals() but forgets hashCode(). They add 10,000 rates to a HashMap. What happens when they query map.get(new CurrencyPair("USD", "EUR"))?"
Correct: Option B) It returns null almost every time because the lookup checks the wrong bucket based on memory address instead of fields. • Debrief: The HashMap uses hashCode() to locate the bucket array index. If hashCode() is not overridden, two logically identical objects produce different hash codes and land in different buckets, making retrieval impossible.
