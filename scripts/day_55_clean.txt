Invariant: Always invoke wait() inside a while() loop, NEVER an if() statement, to defend against spurious wakeups. ⚠️ Failure Mode & tryIt Bug: Failure: Calling wait() inside an if statement causes a thread to wake up after capacity changes and corrupt the buffer (Spurious Wakeup). tryIt Friction: Enclose wait() inside "while (queue.size() == capacity) { wait(); }" to guard against spurious wakeups. 💡 3-Tier Socratic Hint Ladder: [1. Nudge: "Why must wait() always be inside a "while (isFull())" loop instead of "if (isFull())"?"] → [2. Memory: "Because threads can wake up spuriously without being notified, or another thread might have consumed the slot first!"] → [3. Fix: "When it wakes up, it MUST re-check the condition in the while loop before proceeding."] 🧩 Situational Diagnostic Puzzle: "A producer-consumer queue uses notify() instead of notifyAll(). Under heavy load, the application deadlocks with all producer and consumer threads in WAITING state. What caused this thread starvation?" Correct: Option B) notify() wakes only ONE random thread. A producer woke another producer (which saw the queue full and went back to sleep), leaving all consumers asleep forever. • Debrief: notify() wakes a single arbitrary waiting thread. If a producer wakes another producer instead of a consumer, both wait, and the system permanently starves. Use notifyAll().
