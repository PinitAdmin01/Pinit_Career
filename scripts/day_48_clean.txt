Violating this loses objects in HashMaps. ⚠️ Failure Mode & tryIt Bug: Failure: Overriding equals() without overriding hashCode() causes map.get(key) to return null even when the key was previously put into the map! tryIt Friction: Implement both equals() and hashCode() consistently on a custom AccountId key class. 💡 3-Tier Socratic Hint Ladder: [1. Fix: "Override both equals() and hashCode() using Objects.hash(id)."] 🧩 Situational Diagnostic Puzzle: "A developer creates a HashMap with 100,000 entries. Every lookup takes 50 milliseconds ($O(N)$ linear time). Profiling shows all 100,000 keys return hashCode() = 1. What happened?" Correct: Option B) Catastrophic hash collision: all keys landed in bucket #1, collapsing the map into a single linked list / tree chain. • Debrief: A degenerate hashCode() implementation that returns a constant puts all entries into a single bucket. Lookup collapses from $O(1)$ to $O(N)$ (or $O(log N)$ in Java 8 tree bins).
