Concept Invariant &amp; Guardrail Mobile operating systems terminate apps that exceed memory limits (Jetsam on iOS, Low Memory Killer on Android). Developers must inspect memory allocation graphs to find closures retaining native views. Failure Mode: Retaining a reference to a native UIView inside a global JavaScript array prevents iOS from freeing its backing render surface, creating a permanent memory leak. TryIt Friction Challenge: Capture an Xcode Instruments Allocations trace, reproduce a memory leak by repeatedly pushing and popping a screen, and eliminate the retain cycle. 3-Tier Socratic Hint Ladder: 1. Nudge: How do you know if an unmounted screen is actually being garbage collected by iOS? 2. Visual Memory: In Xcode Instruments Allocations, check the count of UIViewController / RCTView instances! If the count increases every time you open and close the screen, you have a leak. 3. Surgical Line Fix: Ensure native view instance counts return to baseline after the screen is popped. Situational Production Puzzle (FAANG / Staff Screen): Scenario: An iOS app crashes with EXCEPTION_FLAG_JETSAM after 15 minutes of user activity. Profiling shows native memory climbing from 45MB to 850MB. Where should the senior engineer look first? Debrief: Jetsam terminations occur when an app exceeds OS memory limits. Uncached high-res images and detached native views held by active JavaScript event closures are the primary causes of massive RAM growth.
